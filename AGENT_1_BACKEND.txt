--------------------------------------------------------------------------------
C1 — INCOGNITO PRECEDENCE IN rpc_device_check
--------------------------------------------------------------------------------
The reliable Incognito signal is "known fingerprint, missing cookie". The client
p_incognito_signal is only corroborating evidence, not the trigger. The check
must block BIND-205 when the cookie is missing on a known fingerprint AND the
client signal confirms private mode. Otherwise BIND-204 CONTACT_ADMIN.

Exact precedence inside rpc_device_check:

  1. PERFORM pg_advisory_xact_lock(hashtextextended(p_fingerprint_hash, 0));
  2. Lookup active binding for p_student_id.
  3. IF binding exists AND binding.fingerprint_hash = p_fingerprint_hash:
       IF cookie valid AND binding.device_id matches p_local_device_id:
          return BIND-200 OK
       ELSIF p_incognito_signal = true:
          return BIND-205 OPEN_NORMAL_BROWSER
       ELSE:
          return BIND-204 CONTACT_ADMIN
  4. IF binding exists AND fingerprint differs:
       return BIND-201 CONTACT_ADMIN
  5. IF no binding AND fingerprint already bound to another active student:
       return BIND-202 CONTACT_ADMIN
  6. IF p_incognito_signal = true:
       return BIND-205 OPEN_NORMAL_BROWSER
  7. ELSE create new binding, set attempt.fingerprint_hash + device_bound = true,
     issue cookie:
       return BIND-200 BOUND

Note the two Incognito checks (step 3 and step 6). BOTH must be present.

--------------------------------------------------------------------------------
C2 — rpc_lookup_matric LOCKING SEMANTICS
--------------------------------------------------------------------------------
The attempt's student_id is bound by the FIRST successful lookup. A later lookup
with a different matric on the same attempt is allowed only BEFORE device-check
has succeeded (i.e. before the student has clicked "Continue to Location Check").
After device-check returns OK, student_id is permanently locked.

Exact rule inside rpc_lookup_matric:

  - If attendance_attempts.student_id IS NULL:
      set student_id = matched student; return OK
  - If attendance_attempts.student_id = matched student:
      return OK (idempotent)
  - If attendance_attempts.student_id IS NOT NULL AND <> matched student:
      IF attendance_attempts.device_bound = false:
          replace student_id (user clicked Edit before confirming)
          return OK
      ELSE:
          return STUDENT_LOCKED (409)

Add a device_bound BOOLEAN NOT NULL DEFAULT false column to attendance_attempts.
rpc_device_check sets it to true when it returns BIND-200 BOUND.

device-check/index.ts (fixes SEC-03, SEC-05, SEC-06, C1):

  const localDeviceId = body.local_device_id ?? body.device_id ?? null;
  const localDeviceIdValid = isValidUuid(localDeviceId) ? localDeviceId : null;

  const fingerprintRaw = body.fingerprint ?? body.fingerprint_hash;
  if (!fingerprintRaw) return 400;
  const fingerprintHash = await hashWithSalt(fingerprintRaw, FINGERPRINT_SALT);

  const cookies = parseCookies(req.headers.get('Cookie') ?? '');
  const trustedCookie = cookies['adun_trusted_device'] ?? null;
  const cookieHash = trustedCookie ? await hmacHash(trustedCookie) : null;

  const { data: result } = await serviceClient.rpc('rpc_device_check', {
    p_student_id: body.student_id,
    p_attempt_id: body.attempt_id,
    p_fingerprint_hash: fingerprintHash,
    p_cookie_token_hash: cookieHash,
    p_local_device_id: localDeviceIdValid,
    p_incognito_signal: body.incognito_signal === true,
  });

  const headers = { ...corsHeaders, 'Content-Type': 'application/json' };
  if (result.action === 'OK' && result.reason === 'BOUND') {
    const newCookie = await signCookie(body.student_id, fingerprintHash);
    headers['Set-Cookie'] = serializeCookie('adun_trusted_device', newCookie, {
      httpOnly: true, secure: true, sameSite: 'Lax',
      path: '/', maxAge: 31536000,
    });
  }
  return new Response(JSON.stringify({
    action: result.action,
    reason: result.reason,
    reference_code: result.reference_code,
  }), { status: 200, headers });
  // NEVER include trusted_device_token in JSON.
