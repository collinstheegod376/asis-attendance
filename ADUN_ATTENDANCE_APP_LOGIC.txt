ADUN ATTENDANCE — FULL APP LOGIC AND WORKFLOW
File name: ADUN_ATTENDANCE_APP_LOGIC.txt
App name: ADUN Attendance
Type: Installable PWA + separate local admin/lecturer web app
Backend: Supabase
Timezone: Africa/Lagos
Hosting: Student PWA on HTTPS; admin/lecturer web on separate host/subdomain

==================================================
0. LOCKED DECISIONS
==================================================

1. Student access is gated by a lecture session link/QR.
   - A session link is one link per lecture session.
   - It is reusable by many students until it expires or is closed.
   - It is not consumed by the first student.
   - QR codes are NOT rotated during a session.
   - Token is validated server-side on every step.

2. Course eligibility uses a lecturer-uploaded roster spreadsheet.
   - Lecturer uploads the list of students allowed to take the course.
   - System validates the upload against the master student spreadsheet/table.
   - Only qualified students can sign attendance.
   - Qualification means:
     a. Student exists in master student table.
     b. Student is on the uploaded course roster.
     c. Student level/program matches course rules if configured.
     d. Student has not already signed this session.

3. Admin sets default and maximum session duration.
   - Lecturer chooses actual duration within the admin maximum.
   - Admin can also create/override sessions if needed.

4. Video step is instructional only.
   - No video recording of the student.
   - Student views instruction video, then proceeds to confirmation.
   - Video completion is recorded in the attempt but is not a security control.

5. Location confirmation is captured as evidence and can enforce a campus geofence.
   - Admin setting: location_mode = enforce | evidence_only.
   - If enforce and campus boundary is configured, student must be inside boundary.
   - Accuracy threshold must be met, default 50 metres.
   - If location fails, student can retry.

6. Selfie retention is configurable.
   - Default: 180 days.
   - Selfie stored in private Supabase Storage.
   - Lecturer views via short-lived signed URL.
   - No public selfie bucket.

7. Late signing is allowed until session expiry.
   - Within grace period after start: present.
   - After grace period but before expiry: late.
   - After expiry: blocked by expired page.

8. Up to 9 subjects means 9 active courses per lecturer.
   - Archived courses do not count.
   - Admin can archive a course to free a slot.

9. Admin only creates lecturer accounts.
   - Admin does not create student accounts.
   - Lecturer has full management of own courses, sessions, roster, QR/link, views, and exports.
   - Lecturer cannot edit or delete attendance records or selfie evidence.
   - Admin can view all, soft-delete lecturers, reassign/archive courses, reset device bindings.

10. Deleting a lecturer is a soft delete.
    - Courses are archived or reassigned.
    - Attendance history is preserved.
    - Audit log records the action.

11. Session tokens are stored hashed server-side.
    - High entropy.
    - No sequential IDs in QR.
    - Token page uses Referrer-Policy: no-referrer.

12. No separate consent screen is added because students signed at admission.
    - Privacy notice remains accessible from the landing/footer.
    - Selfie retention still applies.

13. Rate limiting is enabled.
    - Token validation and matric lookup are rate-limited.
    - Repeated failures are logged.

14. localStorage matric binding is enabled as a soft device lock.
    - After a successful matric lookup, the matric hash is bound to this browser/device.
    - A different matric number on the same browser is blocked until reset.
    - This is not security; it can be bypassed by clearing storage or using another browser.
    - Admin/lecturer can reset a device binding.

==================================================
4. STUDENT SPREADSHEET AND ROSTER
==================================================

Master student spreadsheet columns:
matric_no,surname,first_name,middle_name,program,level,email,phone,search_key

Example:
ADUN/FS/COM/25/01,Doe,John,Ada,Computer Science,400,john@example.com,08000000000,001
ADUN/FS/COM/25/02,Smith,Jane,,Computer Science,400,jane@example.com,08000000001,002

Rules:
- matric_no is primary lookup.
- search_key is last 3 digits helper only.
- Preserve leading zeros.
- Normalize matric to uppercase and trim spaces.
- Matric regex example: ^ADUN/[A-Z]{2}/[A-Z]{3}/[0-9]{2}/[0-9]{2,}$
- Do not rely on last 3 digits alone because collisions can occur above 999.

Course roster upload columns:
matric_no
or
matric_no,surname,first_name,program,level

Roster upload workflow:
1. Lecturer opens course.
2. Lecturer uploads roster spreadsheet.
3. System parses file.
4. For each row:
   a. Normalize matric.
   b. Look up student in students_master.
   c. If not found, mark row invalid.
   d. If found, insert into course_roster.
5. System shows import summary:
   - accepted rows
   - rejected rows with reasons
6. Lecturer can download rejected rows.
7. Roster replace mode must be explicit:
   - append
   - replace all
8. Only students on course_roster can sign for that course.

5. SESSION LINK AND QR LOGIC
==================================================

Creation:
- Lecturer selects course.
- Lecturer creates lecture session:
  title, starts_at, duration within admin max, grace_minutes.
- System generates high-entropy token.
- Store only token_hash.
- QR/link contains:
  https://student-pwa-host/join/<raw-token>
- QR is static for that session until expiry.
- No QR rotation.

Validation on every student step:
- token exists
- token_hash matches
- session status is active or scheduled-but-now-active
- now >= starts_at
- now < expires_at
- session not closed/revoked
- course not archived
- attempt not expired
- student qualified
- student not already signed

Status pages:
/expired      token expired by time
/invalid      unknown/malformed token
/not-started  session not open yet
/closed       lecturer closed/revoked session
/already-signed duplicate attendance
/not-enrolled not on course roster or master table
/unsupported  no camera/geolocation/HTTPS
/offline      network failure

Landing page:
- Logo only.
- “Scan a lecture code to continue.”
- Optional in-app QR scanner.
- No student data.

Expired page:
- Logo.
- “This attendance link has expired.”
- “Ask your lecturer to display a new code.”
- Optional “Scan new code”.

==================================================
6. STUDENT ATTENDANCE WORKFLOW
==================================================

Step 1 — Open link/QR
- Student opens /join/:token.
- Server validates token.
- If invalid/expired/closed/not-started -> status page.
- If valid -> server creates or restores attendance_attempt.
- Attempt expires in 10–15 minutes.
- Attempt token stored in sessionStorage.
- URL token not reused for API calls.

Step 2 — Matric identity
- Student enters matric number.
- Client normalizes and sends to server.
- Server rate-limits lookup.
- Server searches students_master by full matric.
- If not found -> generic not-enrolled/not-found page.
- If found, server checks course_roster.
- If not on roster -> /not-enrolled.
- If qualified, server returns:
  full name, program, level, matric number.
- Student confirms identity.
- localStorage soft binding:
  a. If no binding: store hash(matric), device_id, bound_at.
  b. If binding exists and hash matches: continue.
  c. If binding exists and hash differs: block with “This device is bound to another matric number. Use the original device or contact admin/lecturer to reset.”
  d. Binding can be reset by admin/lecturer.
  e. This is not security; server rules remain authoritative.

Step 3 — Location confirmation
- Browser Geolocation API requests position.
- Capture latitude, longitude, accuracy_m.
- If location_mode = enforce:
  - accuracy must be <= threshold.
  - position must be inside campus boundary if configured.
  - if fail -> retry page.
- If evidence_only:
  - capture and continue even if outside, but mark evidence.
- Store location on attempt.

Step 4 — Live selfie check
- Request camera permission.
- Use face-api.js or MediaPipe Face Mesh + TensorFlow.js.
- Liveness challenge:
  blink, turn head, or smile.
- Detect exactly one face.
- Capture image.
- Upload to private storage path:
  attendance/<session_id>/<student_id>/<attempt_id>.jpg
- Store selfie_path on attempt.
- If no camera/HTTPS -> /unsupported.
- No separate consent screen per decision; privacy notice remains.

Step 5 — Instructional video
- Show instruction video.
- Student taps “I have watched the instruction”.
- Mark video_seen on attempt.
- Video is not a security control.

Step 6 — Submit
- Client sends attempt token and idempotency key.
- Server revalidates:
  token, session status, time, attempt expiry, roster, duplicate.
- Server inserts attendance_record atomically.
- Unique(session_id, student_id) prevents duplicates.
- If duplicate -> /already-signed.
- If success -> generate receipt_id.
- Show confirmation screen:
  ADUN Attendance
  Attendance recorded
  Course code/title
  Student name
  Matric number
  Time
  Status: present/late
  Receipt ID
- Do not show selfie back to student unless required.

==================================================
7. LOCALSTORAGE MATRIC BINDING LOGIC
==================================================

Purpose:
- Prevent accidental use of another matric number on the same browser.
- Not a security boundary.

Implementation:
- Key: adun_device_binding
- Value:
  {
    device_id,
    matric_hash,
    first_bound_at,
    last_seen_at
  }
- device_id is a random UUID stored in localStorage.
- matric_hash = SHA-256(normalized_matric + app_salt).
- Do not store raw matric in the binding object.
- Binding is set after successful matric lookup.
- On later attempts:
  - if no binding -> set binding.
  - if binding matches -> allow.
  - if binding differs -> block.
- Reset paths:
  - admin/lecturer resets device binding.
  - student clears browser data (cannot be prevented).
  - incognito/another browser bypasses (cannot be prevented).
- Server-side optional device_bindings table can mirror this for audit.
- Never use localStorage binding as the only control.

10. SERVER-SIDE SECURITY AND RULES
==================================================

- Use Supabase Edge Functions for student endpoints.
- Do not let anon key select students_master, course_roster, attendance_attempts, attendance_records, or device_bindings.
- RLS:
  - students: no direct access.
  - lecturers: own courses/sessions/rosters/attendance views only.
  - admin: all via admin role.
  - attendance_records: insert only via server function; no update/delete for lecturers.
- Store token_hash, not raw token.
- Store attempt_token_hash.
- Use server time, not device time.
- Use Africa/Lagos timezone.
- Rate limit:
  - token validation per IP/device
  - matric lookup per IP/device
- Log failures.
- Selfie storage private; signed URLs expire quickly.
- Referrer-Policy: no-referrer on token pages.
- No third-party scripts on token pages.
- Service worker:
  - cache app shell only
  - never cache /join, /attend, API responses, selfie uploads, attendance POSTs
- Idempotency key on submit.
- Unique(session_id, student_id).
- Attempt expires in 10–15 minutes.
- Revalidate token on every step.
- Normalize matric consistently.
- Generic error messages for unknown matric to reduce enumeration.

14. EDGE CASES
==================================================

- Student opens link after expiry -> /expired.
- Student opens link before start -> /not-started.
- Lecturer closes session early -> /closed.
- Token malformed -> /invalid.
- Student already signed -> /already-signed with time.
- Student not on master table -> generic not-enrolled/not-found.
- Student on master table but not course roster -> /not-enrolled.
- Roster upload contains unknown matric -> rejected row.
- Roster upload contains duplicate matric -> deduplicate and report.
- Matric with lowercase/spaces -> normalize.
- Matric with leading zeros -> preserve.
- Last 3 digits collide -> full matric lookup used.
- Student changes matric midway -> attempt bound to student_id; blocked.
- Double-tap submit -> idempotency key + unique constraint.
- Location permission denied -> retry/instructions.
- Camera permission denied -> /unsupported or retry.
- No HTTPS -> /unsupported.
- Shared phone with different matric -> localStorage binding blocks until reset.
- Student clears localStorage -> binding lost; server rules still apply.
- Lecturer exceeds 9 active courses -> block with archive message.
- Admin deletes lecturer -> soft delete; courses archived/reassigned; attendance preserved.
- Selfie retention expires -> image deleted; attendance record remains.
- Network drops during upload -> retry with same idempotency key.
- Service worker must not serve stale token pages.
